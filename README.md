# BCM-300 추가 엔티티 (포크)

BCM-300은 폴링 한 번에 홀딩 레지스터 64개를 모두 돌려주지만, 본가 `v2.0.0`은 그중 일부만 엔티티로 만듭니다.
이 포크는 시하스 앱이 보여주는 나머지 값들을 추가로 노출합니다.

| 레지스터 | 도메인 | 이름 | 설명 |
|---|---|---|---|
| R7 | `number` | 예약 주기 / 예약 가동시간 | 몇 시간마다 몇 분 가동할지. 레지스터 하나에 `HHMM`으로 들어 있어 두 엔티티로 나눴고, 한쪽만 바꿔도 나머지 절반은 기기 값을 그대로 유지합니다. |
| R9 | `sensor` | 온돌 현재 온도 | 온돌(난방수) 온도 (℃) |
| R10 | `sensor` | 온수 현재 온도 | 온수 온도 (℃) |
| R11 | `sensor` | 연소 상태 | 정지 / 연소 |
| R12 | `sensor` | 에러 코드 | 0 = 정상, 그 외는 보일러 에러 코드 |
| R13 | `sensor` | 물 상태 | 충분 / 부족 / 이상 |
| R14 | `sensor` | 보일러 연결 | BCM과 보일러 사이의 연결 상태 (온라인 / 오프라인) |

레지스터 의미는 본가 `v1.x`의 `climate.py`에 주석으로 문서화되어 있던 것을 따랐습니다
(`BCM_REG_ONDOLTEMP`, `BCM_REG_WATERST` 등. `v2.0.0` 재작성 과정에서 빠졌습니다).

읽기 전용 값은 기존 `BcmCoordinator`의 폴링 결과를 그대로 쓰므로 통신량이 늘지 않습니다.

## 알려진 제약

- R10(온수 온도)은 온수 온도 센서가 없는 보일러에서 `0`으로 보고될 수 있습니다. 값을 가공하지 않고 그대로 노출합니다.
- R13의 `이상`은 `0`/`1` 이외의 값을 모두 묶은 것으로, 실제 기기에서 확인된 매핑이 아닙니다. 원래 값은 `raw_value` 속성에 있습니다.
- R12의 에러 코드 값별 의미는 공개된 문서가 없어 숫자를 그대로 노출합니다.
- R7의 허용 범위는 `1~24시간` / `0~59분`으로 두었습니다. 공식 문서가 아닌 추정치이며, 기기가 거부하면 쓰기 직후 읽기 검증 단계에서 오류로 보고됩니다.

## 검증

Home Assistant 없이 엔티티가 어떤 값을 보고할지 확인할 수 있습니다.
기기에 닿으면 실제로 폴링하고, 닿지 않으면 기록된 덤프로 대체합니다.

```bash
python3 tools/sihas_poll.py <기기 IP>            # 레지스터 64개 덤프 (읽기 전용)
python3 tools/verify_bcm_entities.py <기기 IP>   # 엔티티 값 + R7 쓰기 경로 검증
```
